# Cleanup

**This lab creates no AWS resources**, so there is nothing to tear down in your account. That is
worth checking rather than assuming, which is what step 1 is for.

## 1. Confirm nothing exists in AWS

There should be nothing to find. This lab creates no endpoint, deployment, store, index, cache,
bucket, log group or repository. It only sends requests and reads what comes back.

**Nothing continues to incur cost after you stop**, because nothing was created. The only usage was
the tokens of a handful of small requests.

## 2. Deactivate the virtual environment

```bash
deactivate
```

Works the same on macOS, Linux and Windows. It returns your terminal to its normal Python. If you
have already closed the terminal, this has effectively happened already.

## 3. Delete the environment, if you want the space back

```bash
rm -rf .venv
```
```powershell
Remove-Item -Recurse -Force .venv    # Windows PowerShell
```

**Safe to delete.** `.venv` holds only the downloaded dependency. Everything you wrote is in
`scripts/contract.py`, which this does not touch. If you come back to the lab later, recreate it
with `SETUP.md` steps 3-5.

## 4. Local files

| File | Keep or remove |
|---|---|
| `scripts/contract.py` | **Yours.** Keep it if you want a record of what you built |
| `PREDICTIONS.md` | **Yours.** Worth keeping — it is the more interesting half |
| `__pycache__/` | Generated by Python. Delete freely; it will come back if you run the lab again |

The lab writes no other files.

## 5. Permissions you added only for this lab

If you created an IAM user, role or policy **solely** to run this lab, remove it now. This is
permissions hygiene rather than resource teardown — nothing is costing you anything, but a
credential that exists for no current reason is worth retiring.

If you used credentials you already had, there is nothing to do.

---

**Verification here means confirming nothing was left behind — not confirming that a deletion
succeeded.**
